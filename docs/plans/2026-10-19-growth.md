# NoteIt Growth Implementation Plan

**Goal:** Give NoteIt a website, a public roadmap with voting, better issue and discussion templates, contributor onboarding, a press kit and demo video, a launch after the first full release that contains all of wave 1 (automation, markdown-storage, linking, organise; after the wave 0 foundations), the official Homebrew cask when it qualifies (with the `noteit` command line tool once automation ships it), and a way to read public numbers, all without tracking, accounts or a server.

**Architecture:** Nothing in the app changes. The work is files in the repo and settings on GitHub:
- `site/` holds a hand-written static website (HTML and one CSS file, no scripts), deployed by a new Pages workflow that stamps the latest release's version, URL, size and SHA-256 into two pages and zips the press kit.
- `scripts/check_site.py` (Python 3 standard library) is the site's linter and runs before every deploy.
- `.github/labels.yml` plus `scripts/sync_labels.sh` keep labels as code; Discussions categories are set by hand.
- `scripts/project_stats.sh` reads public GitHub and Homebrew numbers with `gh` and `curl`.
- The tap cask is aligned with homebrew/cask style now, gains the `binary` line for the `noteit` command line tool once automation's M4 ships it (growth owns that line, program design §12), and is moved to homebrew/cask once the notability thresholds are met.

**Tech stack:** HTML5, CSS (no preprocessor), Python 3 standard library, Bash, `gh` CLI, GitHub Actions (`actions/upload-pages-artifact`, `actions/deploy-pages`), Homebrew (`brew audit`, `brew style`), `sips` and `ffmpeg` for media. No new Swift code and no new Swift dependencies.

**Spec:** `docs/specs/2026-10-19-growth-design.md`. Program contract: `docs/specs/2026-10-19-program-design.md`, which wins if the two disagree.

"The wave 1 release" in this plan always means the first full release that contains all of wave 1 (automation, markdown-storage, linking, organise), which comes after the wave 0 foundations.

## Conventions for every task

- Work from the repository root. Never touch `~/Library/Application Support/NoteIt`; screenshots and the demo use `NOTEIT_DATA_DIR=.selftest/press` (already gitignored).
- Site check: `python3 scripts/check_site.py site` must print `OK: <n> pages` and exit 0. After stamping: `python3 scripts/check_site.py _site --stamped`.
- Script tests: `python3 -m unittest discover -s scripts/tests -v` must end with `OK`. Every task that produces a file in the repo adds its checks here, so CI (Task 10) runs them on every push. Tests that need a tool CI may not have (`ffprobe`, `brew`) use `unittest.skipUnless` and are run locally before merge.
- YAML in tests is read through `scripts/tests/yamlutil.py` (`load(path)` runs `ruby -ryaml -rjson` and returns the parsed JSON), so the tests stay standard-library Python.
- Manual checklists are only for work no script can check: recording video, posting, GitHub settings pages and external reviews.
- YAML syntax check (no extra tools): `ruby -ryaml -e 'ARGV.each { |f| YAML.load_file(f) }; puts "yaml ok"' <files>` prints `yaml ok`.
- App checks are only needed when a task touches `scripts/build_app.sh` or `Sources/` (none do): `swift build 2>&1 | tail -3` ends with `Build complete!`.
- Local preview: `python3 -m http.server -d site 8000`, then open `http://localhost:8000/`. Stop it by PID afterwards.
- Pin third-party actions by commit SHA with the version in a comment, as `release.yml` does.
- Copy follows `design/BRAND.md`: the name is always **NoteIt**, UI labels in Title Case, plain sentences, no emojis, no hype words ("revolutionary", "blazing", "game-changing").
- Claims follow spec 1.3: the site and launch copy describe only features in the current full release. Anything else is written as "planned" and links to `https://github.com/rutbergphilip/noteit/blob/main/docs/roadmap.md`. Never "coming soon", "beta" or dates.
- Commit after each task with Conventional Commits and sign-off, e.g. `git commit -s -m "docs(site): add privacy page"`. Never amend, rebase or force-push `main`.
- Tasks that change GitHub settings (Discussions, labels, repo fields) list the exact `gh` command; run them only after the matching files are merged to `main`.

## Frozen interfaces

There are no Swift interfaces. These names are relied on by several tasks and by people outside the repo, so they don't change once merged.

**Site URLs** (relative to `https://rutbergphilip.github.io/noteit/`): `/`, `/features/`, `/compare/`, `/switch/`, `/switch/apple-notes/`, `/switch/bear/`, `/switch/obsidian/`, `/switch/notion/`, `/switch/evernote/`, `/privacy/`, `/download/`, `/press/`, `/press/noteit-press-kit.zip`, `/media/noteit-demo.mp4`. `/plugins/` (`site/plugins/index.html`) is added and owned by `plugins` (its Task 19), together with the `noteit-plugins` repository and its contribution guide; no growth task creates them, and growth's `check_site.py`, shared blocks and `test_no_banned_words` apply to that page like any other.

**Placeholders** (only in `site/index.html` and `site/download/index.html`):

| Placeholder | Value |
|---|---|
| `@@VERSION@@` | `tagName` without the `v`, e.g. `0.4.0` |
| `@@DMG_URL@@` | `https://github.com/rutbergphilip/noteit/releases/download/v<version>/NoteIt-<version>.dmg` |
| `@@DMG_SIZE@@` | asset size in MB with one decimal, e.g. `9.8 MB` |
| `@@DMG_SHA256@@` | asset `digest` without the `sha256:` prefix |
| `@@RELEASE_DATE@@` | `publishedAt` as `YYYY-MM-DD` |

**Shared page blocks:** every HTML page has `<!-- header -->…<!-- /header -->` and `<!-- footer -->…<!-- /footer -->`, byte-identical across pages except that links are written root-relative with the `/noteit/` base (`href="/noteit/features/"`).

**Script command lines:**

```
python3 scripts/check_site.py <dir> [--stamped]
  exit 0, prints "OK: <n> pages"; exit 1, prints "<file>: <problem>" per problem
scripts/stamp_site.sh <srcdir> <outdir>
  needs GH_TOKEN or gh auth; copies, stamps, builds <outdir>/press/noteit-press-kit.zip; exit 1 if no full release
scripts/sync_labels.sh [--dry-run]
  reads .github/labels.yml, runs gh label create --force per label; never deletes labels
scripts/project_stats.sh [owner/repo]
  default rutbergphilip/noteit; prints a Markdown table to stdout; writes nothing
```

**`.github/labels.yml` shape:**

```yaml
- name: "area: sync"
  color: "3A3FD9"
  description: "Sync, backends and encryption"
```

**Workflow:** `.github/workflows/pages.yml`, name `Pages`, triggers `push` (main, paths `site/**`, `design/press/**`, `scripts/check_site.py`, `scripts/stamp_site.sh`, `.github/workflows/pages.yml`) and `workflow_dispatch`. `release.yml` calls it with `gh workflow run pages.yml --ref main` as the last step of its `publish` job. That step stays when the `homebrew` job is removed in Task 19.

**Cask CLI line** (written by `scripts/update_cask.sh` right after `app "NoteIt.app"`, only when `scripts/build_app.sh` at the release tag has an embeds row for `Contents/Helpers/noteit`, so the app bundles `Contents/Helpers/noteit`):

```ruby
binary "#{appdir}/NoteIt.app/Contents/Helpers/noteit"
```
