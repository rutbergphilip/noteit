# NoteIt for iPhone and iPad Implementation Plan

**Goal:** Ship a native iPhone and iPad app that syncs with the Mac through the user's existing end-to-end encrypted store. It starts as a capture tool (M1, TestFlight), becomes a reader, search and editor (M2, App Store), and then adds the iPad layout, attachments, offline library, Shortcuts and iCloud Drive folders (M3).

**Architecture:**
- Shared logic lives in Foundation-only SwiftPM targets that build for macOS and iOS (program spec §1). `Package.swift` platforms are declared once in foundations; this plan doesn't change them.
  - `NoteItCore` (from foundations): models, `SidebarSelection`, `LibraryQuery`, folding, `FuzzyMatcher`, the query language, `NoteLink`, the `URLCommand` parser, `library.json` coding, the capture title rule and the trash policy. This plan adds the `NoteLibrary` protocol.
  - `NoteItSync` (existing): gains `SyncProvider`, `PairingPayload`, a join-only format policy, a capture scope, on-demand bodies and a join-only connect that takes a `StoreCredential`. `Keyring`, `StoreCredential`, `StoreSession`, manifest features, `SyncEngine.ensureFeature(_:backend:session:currentDeviceID:confirm:)`, `DeviceInfo` and `RawMetaOverlay` come from foundations.
  - `NoteItDoc` (Foundation only, from foundations): this plan adds the `DocText` editing model. The AppKit converter stays in `NoteItDocAppKit`, which the phone never links.
  - `NoteItMarkdown` (from `markdown-storage`): Markdown output for Get Note Text.
  - `NoteItMobileKit` (new, depends on `NoteItCore`, `NoteItDoc`, `NoteItSync`, `NoteItMarkdown`): the phone's library store, sync adapter and runner, capture inbox, body cache, URL routing and widget snapshot. Tested with `swift test` on the Mac.
- The iOS app is an Xcode project generated by XcodeGen from `mobile/project.yml`. It contains only SwiftUI views, a UIKit text view, the share and widget extensions, App Intents and glue. Its tests are smoke tests.
- The Mac app gains one feature: **Add iPhone or iPad…**, which shows a pairing QR code and an 8-character code.

**Tech Stack:** Swift 6.3 toolchain in Swift 5 language mode, SwiftPM, XcodeGen, SwiftUI, UIKit (TextKit 2), WidgetKit, App Intents, BackgroundTasks, VisionKit (DataScannerViewController), AVFoundation, LocalAuthentication, CoreImage (QR on the Mac), CryptoKit, Security. No third-party dependencies in the app. iOS 17 minimum, iPhone and iPad.

**Spec:** `docs/specs/2026-10-19-mobile-design.md`

**Prerequisites:** foundations (`docs/plans/2026-10-19-foundations.md`: `NoteItCore`, the `NoteItDoc` split with `NoteItDocTestSupport` and the `noteit-doc` golden vectors (task 2.4), `StoreSession` with manifest features, `DeviceInfo`, `RawMetaOverlay` in `NoteItSync`, `ImportHygieneTests`), the rest of Phase 0 of `docs/plans/2026-10-13-web-app.md` (`bodies/`, `BodyFormat`, `DocDerivation`, `fixtures/golden/doc-convert.json`, the conversion sweep, and `noteit-doc` in `StoreFeature.supported`), and `NoteItMarkdown` from `markdown-storage` are merged. `Keyring` and `StoreCredential` come from foundations Tasks 3.2–3.3 (wave 0), not from `sync-security`. The locked-note body format is sync-security's milestone 5, which lands in wave 3 after web-app Tasks 0.4–0.5; the phone never opens sealed bodies, so its locked-note tasks run against fixture stores and don't wait for it. M0 can start before they land only for tasks marked "no prerequisites".

**Waves:** this plan runs in wave 3 (program spec §1), after sync-security's M1–M4 in wave 2. Task 0.8 moves `SyncProvider` into `NoteItSync` only after sync-security Task 3.4 has added `.webdav`, so the move carries every case.

## Conventions for every task

- Package tests (from the repository root): `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter <Suite> 2>&1 | tail -20`. Expected: `Executed N tests, with 0 failures`.
- Mac app build: `swift build 2>&1 | tail -3` and `swift build -c release 2>&1 | tail -3` both end with `Build complete!`.
- iOS build of a package product: `xcodebuild -scheme <Product> -destination 'generic/platform=iOS Simulator' build 2>&1 | tail -3`. Expected: `** BUILD SUCCEEDED **`.
- iOS simulator destination: `scripts/ios_sim_destination.sh [iphone|ipad]` reads `xcrun simctl list devices available --json` and prints `platform=iOS Simulator,id=<UDID>` for the newest available iPhone (or iPad). No device name is hard-coded anywhere.
- iOS app tests: `cd mobile && xcodegen generate && xcodebuild -project NoteItMobile.xcodeproj -scheme NoteItMobile -destination "$(../scripts/ios_sim_destination.sh iphone)" test 2>&1 | tail -5`. Expected: `** TEST SUCCEEDED **`. These run in the `ios` CI job only.
- iOS tests are smoke tests (launch, a route, a render, a capture). Any logic worth testing goes into `NoteItMobileKit`, `NoteItDoc` or `NoteItSync` and is tested with `swift test`.
- Never touch real data. Mac runs use `NOTEIT_DATA_DIR=<project>/.selftest/<name>`. Simulator runs use a fresh simulator (`xcrun simctl erase`) and a MinIO bucket or `FolderBackend` path under `.selftest/`.
- Library targets added or changed here import Foundation, CryptoKit and Security only (plus each other). The one exception is `NoteItMobileKit`, which may also import ImageIO and CoreGraphics (both available on iOS and macOS) for `MobileImageNormalizer`. `ImportHygieneTests` (from foundations) checks this with its per-target allow list; task 1.1 adds `NoteItMobileKit` to it with that allow list.
- Commit after each task with Conventional Commits, scope `mobile` (or `sync`, `core`, `doc` for shared targets), e.g. `feat(core): add NoteLibrary protocol`. Never amend, rebase or force.
- No `#Preview`. Comments only where something is non-obvious. Plain user-facing wording exactly as in the spec.
- Example names in fixtures and UI tests are neutral ("Studio", "Groceries").
- The Mac app must behave identically after every M0 task: `swift test` (all suites) stays green.

    public var region: String?

    public var prefix: String?
