# NoteIt Sharing Implementation Plan

**Goal:** Let the user share a note as an encrypted link, publish a notebook as a static website, and share an encrypted notebook with other people, all through storage the user owns and without a server run by NoteIt. The work ships in five milestones that each stand on their own.

**Architecture:** Everything that can be tested without AppKit goes into `NoteItSync`, in three new folders:
- `Sharing/` — the share-link format (`ShareLinkCodec`) and `PublicObjectWriter`, implemented by the existing `S3Backend` and `FolderBackend`.
- `Publishing/` — slugs, the site diff, the site manifest, RSS, and a GitHub Git Data API client.
- `Spaces/` — member identity, the signed membership log, HPKE key wrapping, `SpaceCipher` (a `SyncCipher`), invitations, and a `SpaceClient` actor that drives one space and runs rotation through sync-security's `RekeyRunner`.

Sharing builds on the foundations seams (program §2) and doesn't redefine them: `StoreSession` and the manifest types, the `RemoteLayout` registry with `.storeKey`/`.spaceKey`/`.unsealed` sealing and `RekeyScope`, `NoteStore.editBody`, `NoteMeta.isLocked`, `URLRouteRegistry`, `LocalAPIRouteRegistry` and the frozen Settings, menu and sidebar tables. Re-encryption uses `RekeyRunner` and its `rekeyAck` fence from `sync-security`.

The app target adds publish destinations, the Settings › Sharing tab, share-link and site controllers built on `HTMLWriter`, a static viewer page resource, sync scopes in `NoteStore+Sync` and `NoteStoreSyncAdapter` so each shared notebook syncs to its own space with the unchanged `SyncEngine`, the sheets, menus and palette commands, the `join` link host and the `sharing.*` Local API routes.

**Tech Stack:** Swift 6.3 toolchain in Swift 5 language mode, SwiftPM, Foundation/URLSession, CryptoKit (AES-GCM, HKDF, `Curve25519`, `HPKE` on macOS 14, which `Package.swift` already targets), CommonCrypto (PBKDF2, through the existing `KeyDerivation`), Security (keychain, through `SecItemStore`), SwiftUI/AppKit, WebKit (tests of the viewer only). The viewer is plain JavaScript using WebCrypto. No new dependencies.

**Spec:** `docs/specs/2026-10-19-sharing-design.md`

**Milestones:**

Sharing is in wave 3. Foundations, automation, linking, organise and sync-security's wave 2 milestones (1–4, including `RekeyRunner`) are in place before M1 starts. Locked notes (sync-security milestone 5) also land in wave 3, after web-app Tasks 0.4–0.5. Sharing reads locked state only through foundations' `NoteMeta.isLocked`, so its locked-note checks are tested with fixture notes and don't wait for that milestone.

| Milestone | Ships | Tasks | Size | Needs |
|---|---|---|---|---|
| M1 Share links | Destinations (Folder, S3 presets), share links with viewer, expiry, passphrase, update, delete, Shared Links list, Local API routes for links | 1–9 | about 2 weeks | — |
| M2 Publish to Folder and S3 | Renderer, slugs, links, RSS, incremental upload, automatic republish, Local API publish route | 10–15 | about 2 weeks | M1 (destinations) |
| M3 GitHub Pages | GitHub Pages destination for sites | 16–17 | about 1 week | M2 |
| M4 Shared notebooks on S3 and folders | Identity, log, cipher, key wrapping, invitations, roles, removal with rotation, sync scopes, `join` links, UI | 18–29 | about 6 weeks | M1 (Settings tab) |
| M5 Other Macs and spaces on your self-hosted NoteIt Server | Same identity on your other Macs; shared notebooks on your self-hosted NoteIt Server | 30–32 | about 3 weeks, plus server work | M4, personal Sync, and the `web-app` server for task 31 |

Each milestone ships on its own and leaves the app working. M2 and M4 can be built in parallel by different people once M1 is merged.

M4 is the riskiest part. It ships behind a **Shared notebooks (preview)** label in the Share Notebook sheet until it has been used by real groups for one release.

## Conventions for every task

- Test command (from the repository root): `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter <Suite> 2>&1 | tail -20`. Expected: `Executed N tests, with 0 failures`.
- App build: `swift build 2>&1 | tail -3` and `swift build -c release 2>&1 | tail -3` must both end with `Build complete!` and 0 errors.
- Never touch real user data in `~/Library/Application Support/NoteIt`. When running the app, set `NOTEIT_DATA_DIR=<project>/.selftest/<name>` (already gitignored). Shared-notebook tests with two people use two data folders, `.selftest/sharing-owner` and `.selftest/sharing-member`, and a shared folder `.selftest/space-share`.
- Network tests use `URLProtocol` stubs, like `Tests/NoteItSyncTests/S3BackendTests.swift`. The opt-in MinIO tests follow `LiveS3EmulatorTests.swift` and are skipped unless its environment variables are set.
- Commit after each task with Conventional Commits, scope `sharing`, e.g. `feat(sharing): add share link codec`. Never amend, rebase or force.
- No `#Preview`. Comments only where something isn't obvious.
- `NoteItSync` additions import only Foundation and CryptoKit (no AppKit), are `public` where the app needs them, and are `Sendable`-correct.
- The `noteit/v1/` wire format is frozen. New remote objects live under `noteit/space/v1/`, `noteit/identity/v1/` and the destination's `s/` and site paths only.
- Every user-facing string comes from the spec. Commands are added to `PaletteCommandRegistry` with camelCase IDs, menu shortcuts only through `MenuShortcutCommand` (updating `MenuShortcutRules` and `docs/keyboard-shortcuts.md` in the same task), no global hotkeys.
- Manifest, `StoreFeature`, `StoreSession` and `RemoteLayout` come from foundations; `RekeyRunner` comes from `sync-security`. This plan doesn't modify `Model/Manifest.swift` or add its own re-encryption pass. It owns the check that accepts `noteit-space` only in a space session (program §4 rule 2).
- Note text is changed only through `NoteStore.editBody`. Locked state is read from `NoteMeta.isLocked`; no stubs.
- Per-Mac files (`shares.json`, `spaces.json`, `sites/`, and per-space state in `spaces/<id>/`) live in `NoteStore.rootURL`, never in a Markdown library's content folder.
- Local API routes are registered by this plan through `LocalAPIRouteRegistry.shared.register`, with route ids `sharing.<name>`, an explicit scope, and `APIErrorCode` errors only.
- Secrets only in the keychain service `AppIdentity.bundleID + ".sharing"` through `SecItemStore`. Never log keys, link keys, codes, tokens or passphrases.

public enum SpaceLayout {
    public static let root = "noteit/space/v1/"
    public static func logEntry(_ seq: Int) -> String                // "noteit/space/v1/log/0000000042.json"
    public static func memberKey(epoch: Int, member: MemberID) -> String
    public static func inviteKey(epoch: Int, invite: String) -> String
    public static func profile(_ member: MemberID) -> String
    /// A space's device ID for SyncEngine.init, SpaceSession.connect, RekeyRunner and ensureFeature: "<member-id>/<UUID>",

    // are .unsealed and never re-sealed; profiles/ (depth 1) is .storeKey (the space key in a space session);
    // RemotePrefix(path: "noteit/v1/devices/", depth: 2, sealing: .storeKey, owner: "sharing") for space device records.
    // The feature name is the foundations StoreFeature for "noteit-space"; it isn't redefined here.
}
public enum SpaceLogBody: Codable, Sendable, Equatable {

    case remove(member: MemberID)
    case leave(member: MemberID)
    case rotate(epoch: Int, keyCommitment: Data)
}

    public var seq: Int, space: UUID, prev: Data, at: Date, body: SpaceLogBody
    public static func signed(_ entry: SpaceLogEntry, by signer: SpaceSigner, identity: MemberIdentity) throws -> Data  // file bytes
}
public enum SpaceSigner: Equatable, Sendable { case member(MemberID), invite(String) }
public struct SpaceMember: Sendable, Equatable { public var keys: MemberPublicKeys; public var role: SpaceRole }
public struct PendingInvitation: Sendable, Equatable { public var keys: MemberPublicKeys; public var role: SpaceRole; public var expiresAt: Date }
public struct SpaceState: Sendable, Equatable {
    public var space: UUID
    public var owner: MemberID
    public var members: [MemberID: SpaceMember]
    public var invitations: [String: PendingInvitation]
    public var epoch: Int
    public var keyCommitment: Data
    public var headSeq: Int
    public var headHash: Data
    public func canWrite(_ member: MemberID) -> Bool
}
public enum SpaceLogError: Error, Equatable { case badSignature(Int), brokenChain(Int), gap(Int), notAllowed(Int), inviteUsed(Int), inviteExpired(Int), rolledBack, forked }
public enum SpaceLog {
    /// `files` are entry file bytes by seq. Verifies everything against `ownerKeys`, the trust anchor.
    /// `through` stops the replay at that entry, whose hash must match (otherwise `.forked`); a rotation uses it to
    /// rebuild the old cipher's state at `SpaceRotationState.preRemovalHead` (spec §4.8). nil replays every entry.
    public static func replay(_ files: [Int: Data], space: UUID, ownerKeys: MemberPublicKeys, knownHead: (seq: Int, hash: Data)?,
                              through: (seq: Int, hash: Data)? = nil) throws -> SpaceState
}
public enum SpaceKeyWrap {
    public static func commitment(space: UUID, epoch: Int, key: SymmetricKey) -> Data
    public static func wrap(_ key: SymmetricKey, space: UUID, epoch: Int, to recipient: MemberPublicKeys, recipientLabel: String, wrapper: MemberIdentity) throws -> Data
    public static func unwrap(_ file: Data, space: UUID, epoch: Int, recipientLabel: String, identity: MemberIdentity, wrapperKeys: MemberPublicKeys, commitment: Data) throws -> SymmetricKey
}
public final class SpaceCipher: SyncCipher, @unchecked Sendable {   // state behind a lock
    public init(space: UUID, identity: MemberIdentity, state: SpaceState, keys: [Int: SymmetricKey])
    public func update(state: SpaceState, keys: [Int: SymmetricKey])
    public func seal(_ plain: Data, context: String) throws -> Data
    public func open(_ sealed: Data, context: String) throws -> Data   // signer checked per context (spec §4.4 table)
}
public enum SpaceCipherError: Error, Equatable { case badFormat, staleEpoch(Int), signerNotAllowed, badSignature, decryptFailed }
/// Epoch keys on this Mac (spec §4.6, §4.9). The app's implementation is the keychain (`<bundleID>.sharing`,
/// accounts space-<UUID>-epoch-<n> and space-<UUID>-epoch-<n>-pending); tests use InMemorySpaceKeyStore.
public protocol SpaceKeyStore: Sendable {
    func key(space: UUID, epoch: Int, pending: Bool) throws -> SymmetricKey?
    func setKey(_ key: SymmetricKey, space: UUID, epoch: Int, pending: Bool) throws
    func deleteKey(space: UUID, epoch: Int, pending: Bool) throws
    func pendingEpochs(space: UUID) throws -> [Int]
    /// Moves the pending entry to the current one; no-op when there is no pending entry.
    func promotePending(space: UUID, epoch: Int) throws
    /// The in-flight rotation (spec §4.8), written before the remove or downgrade entry is appended and cleared when
    /// the old epoch's key files are deleted. nil when no rotation is in flight.
    func rotationState(space: UUID) throws -> SpaceRotationState?
    func setRotationState(_ state: SpaceRotationState?, space: UUID) throws
}
/// The log head just before the `remove`, `setRole` downgrade or `leave` entry that a rotation follows. The old
/// cipher's signer acceptance is the state replayed through this head; the new cipher uses the post-removal state.
public struct SpaceRotationState: Codable, Sendable, Equatable {
    public var epoch: Int                  // the new epoch
    public var preRemovalHeadSeq: Int
    public var preRemovalHeadHash: Data
}
public final class InMemorySpaceKeyStore: SpaceKeyStore, @unchecked Sendable { public init() }
/// What launch recovery did with one pending epoch key (spec §4.6).
public enum SpacePendingOutcome: Sendable, Equatable {
    case promoted(epoch: Int)           // its log entry was committed; it is now current and the operation continued
    case discarded(epoch: Int)          // the log has that epoch with another commitment
    case resumed(epoch: Int)            // no log entry: re-uploaded and verified the key file, then committed
    case cancelled(epoch: Int)          // no log entry and the user cancelled: pending entry and keys/<n>/ files deleted
}
public enum SpaceStagingError: Error, Equatable { case keyFileMismatch(epoch: Int), cancelNotAllowed(epoch: Int) }
public struct SpaceLocation: Codable, Sendable, Equatable {
    public enum Kind: String, Codable, Sendable { case s3, folder, server }
    public var kind: Kind
    public var endpoint: URL?, region: String?, bucket: String?, prefix: String?, pathStyle: Bool?
    public var folderHint: String?
    public var serverURL: URL?
}
public struct InvitePayload: Codable, Sendable, Equatable {
    public var space: UUID, name: String, location: SpaceLocation
    public var accessKeyID: String?, secretAccessKey: String?
    public var owner: MemberPublicKeys, role: SpaceRole, inviteID: String
    public var inviteAgreementKey: Data, inviteSigningKey: Data, expiresAt: Date
}
public enum InviteCodec {
    public static let iterations = 600_000
    public static func makeCode() -> String                              // "XXXX-XXXX-XXXX"
    public static func link(_ payload: InvitePayload, code: String) throws -> URL   // noteit://join#v1.<id>.<sealed>
    public static func open(_ link: URL, code: String) throws -> InvitePayload
}
public enum InviteError: Error, Equatable { case notAnInvitation, wrongCode, expired, alreadyUsed, revoked }
public struct SpaceStatus: Sendable, Equatable { public var state: SpaceState; public var myRole: SpaceRole }
public actor SpaceClient {
    /// `deviceID` is this Mac's device ID in the space, SpaceLayout.deviceID(member: identity.id, device:): the one
    /// given to the space's SyncEngine.init. The client passes it to SpaceSession.connect, to RekeyRunner(deviceID:)
    /// and as currentDeviceID to ensureFeature.
    public init(space: UUID, backend: StorageBackend, identity: MemberIdentity, deviceID: String, keys: SpaceKeyStore, ownerKeys: MemberPublicKeys, knownHead: (seq: Int, hash: Data)?)
    /// Staged (spec §4.6): pending epoch-0 key in `keys`, owner's key file uploaded and read back, then the create
    /// entry and the manifest. Called again with a pending epoch-0 key and no log entry 0, it resumes from step 2.
    public static func create(space: UUID, backend: StorageBackend, identity: MemberIdentity, deviceID: String, keys: SpaceKeyStore, name: String) async throws -> SpaceClient
    /// Cancels an unfinished create: deletes the pending epoch-0 key and noteit/space/v1/keys/0/. Throws
    /// cancelNotAllowed when log entry 0 exists.
    public static func cancelCreate(space: UUID, backend: StorageBackend, identity: MemberIdentity, keys: SpaceKeyStore) async throws
    public static func join(_ invite: InvitePayload, backend: StorageBackend, identity: MemberIdentity, deviceID: String, keys: SpaceKeyStore, displayName: String) async throws -> SpaceClient
    /// Launch recovery for staged rotations (spec §4.6), one outcome per pending epoch. `cancel` is honoured only for
    /// epochs whose operation has no committed entry; otherwise the client resumes.
    public func finishPending(cancel: Bool, progress: @escaping @Sendable (RekeyProgress) -> Void) async throws -> [SpacePendingOutcome]
    public func refresh() async throws -> SpaceStatus
    public var cipher: SpaceCipher { get }
    public func invite(role: SpaceRole, expiresAt: Date) async throws -> (inviteID: String, agreementKey: Data, signingKey: Data)
    public func revokeInvite(_ inviteID: String) async throws
    /// Downgrades and removals append the entries, rotate, then re-seal through RekeyRunner in .spaceEpoch mode.
    public func setRole(_ member: MemberID, _ role: SpaceRole, progress: @escaping @Sendable (RekeyProgress) -> Void) async throws
    public func remove(_ member: MemberID, progress: @escaping @Sendable (RekeyProgress) -> Void) async throws
    public func leave() async throws
    public func profiles() async throws -> [MemberID: String]
    public func setProfile(displayName: String) async throws
}

// NoteItSync — Spaces/SpaceSession.swift
public enum SpaceSession {
    /// Opens the space's noteit/v1/ store as a space session through foundations'
    /// connectSession(backend:kind:credential:deviceName:createIfMissing:encrypted:initialFeatures:supported:cipher:) with
    /// backend, kind: .space, credential: nil (the cipher is supplied), deviceName: "" (a space never gets a keyring,

- **Program contract:** no server or account run by NoteIt; `noteit/v1/` record formats are unchanged and the engine gets no sharing-specific change (re-encryption uses sync-security's `RekeyRunner` with the space ciphers, the `rekeyAck` fence with removed members excluded, and `rebaseline(newKeyID:)`; space device records sit at `noteit/v1/devices/<member-id>/<UUID>.json` because the space device ID is `<member-id>/<UUID>`, and their owner comes from that key alone); space creation and epoch rotation are staged so a committed epoch always has the owner's verified key (24, 26); store sessions, manifests and features come from foundations, with `noteit-space` in a `formatVersion` 2 manifest accepted only by a space session, a check sharing owns; new remote prefixes are registered in `RemoteLayout` with sealing, depth and key test vectors; read-only writes return `403 read_only`; per-space state lives in `spaces/<id>/`; note text changes only through `editBody`; locked notes are never shared or published; data files live in `NoteStore.rootURL`; the Sharing tab, File › Share ▸ items, palette IDs and ⌥⌘L follow the frozen tables; the `join` host goes through `URLRouteRegistry`; Local API routes are registered as `sharing.*` with `APIErrorCode` errors; no global hotkeys.
- **Risk:** M4 is the largest and riskiest. Its crypto pieces (18–22) are pure and fully unit-tested before any UI exists, the engine is reused rather than forked, and the feature ships labelled as a preview.
- **Honest limits:** expiry depends on the viewer and on NoteIt running; storage-level deletes and freezing can't be stopped cryptographically; removal can't take back what a person already has; the owner's Mac is a single point of management. All are stated in the spec and documented in task 9 and task 29.
- **Type consistency:** `ShareLinkCodec`, `PublicObjectWriter`, `SiteDiff`, `SpaceLog`, `SpaceCipher`, `SpaceClient`, `LibrarySyncScope` and `HTMLWriterOptions` are used with the same signatures in every task that names them.
