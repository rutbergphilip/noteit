# NoteIt Web Implementation Plan

**Goal:** Ship a self-hostable NoteIt web app (Nuxt) that is a full end-to-end-encrypted sync peer of the native macOS app. It reads and writes the same `noteit/v1/` store and ships as one Docker image with a volume for homelabs.

**Architecture:**
- **Phase 0 (native):** introduce a portable note body, `noteit-doc` (ProseMirror-compatible JSON, versioned), and the `noteit-doc` store feature (envelope `bodyFormat` + `bodyVersion`, crash-safe versioned noteit-doc bodies under `noteit/v1/bodies/`). The `NoteItDoc` targets, the converter, the golden vectors and `RandomDocGenerator` (Tasks 0.1–0.3) moved to wave 0 foundations step 2 (`docs/plans/2026-10-19-foundations.md`), split into `NoteItDoc`, `NoteItDocAppKit` and `NoteItDocTestSupport`. The manifest, `StoreFeature` and `StoreSession` types come from sync-security (foundations step 3); Task 0.4 consumes them. Everything after Phase 0 runs in wave 3 (program spec `docs/specs/2026-10-19-program-design.md` §2).
- **Web:** a pnpm workspace in `web/`:
  - `@noteit/core`: a pure TS port of crypto, formats, planner, engine and storage, verified against the vectors;
  - `@noteit/doc`: schema, TipTap extensions and derivations;
  - a Nuxt 4 SPA. Its Web Worker runs the sync engine with WebCrypto and IndexedDB.
- **Server mode (default):** a Nitro server proxies ciphertext to a disk store or upstream S3. One instance serves several people: accounts (argon2id passwords, optional OIDC), invites, an admin role and quotas, with a fully isolated store namespace per user. Browsers use `/api/storage`; native apps and rclone use an S3-compatible subset at `/s3` with per-user keys.
- **Direct mode:** the same client build, served statically (any static host, or the image with `NOTEIT_MODE=static`), talks straight to the user's S3-compatible bucket over CORS, with the S3 key sealed in IndexedDB under the passphrase.
- **Format upgrade:** automatic when safe. A v2 native client adds `noteit-doc` to a store's `features` on its first clean pass, through `ensureFeature`, which asks the user first if a device in `devices/` can't read it; it then converts notes in the background. Everything keys on `features ∋ noteit-doc`, never on `formatVersion`. The web never converts and shows "Open NoteIt on your Mac once to finish setting up web access" on a store without `noteit-doc`.
- **UI:** NoteIt's design tokens (`Sources/NoteIt/Design/Tokens.swift`) and the assets in `design/`.

**Tech Stack:**
- Swift side: Swift 6.3 / SwiftPM / XCTest; the `NoteItDoc` targets themselves are built in foundations step 2.
- Web side:
  - Node 24, pnpm 11, TypeScript 5 (strict), Vitest, fast-check;
  - Nuxt 4 (Vue 3, Nitro node-server), Pinia, TipTap 2/ProseMirror;
  - `idb`, Comlink, DOMPurify, nuxt-security, `@node-rs/argon2`, `openid-client` (no PWA module: v1 ships no service worker, spec §4.4);
  - `fs-ext` pinned exactly at `2.1.1` (`flock(2)` instance lock, compiled with node-gyp in the Docker build stage);
  - Playwright with Chromium, Firefox and WebKit, `oauth2-mock-server` (mock OIDC provider in tests).
- Deployment: Docker (node:24-alpine) and docker-compose, plus a static tarball. Floci S3 is used for interop tests and the direct-mode browser E2E.

**Spec:** `docs/specs/2026-10-13-web-app-design.md`. Section numbers like "§2.3" below refer to it. The spec's §2 is the byte-level format contract.

## Conventions for every task

- Swift tests: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter <Suite> 2>&1 | tail -20`. App build: `swift build 2>&1 | tail -3` must end with `Build complete!`.
- Web tests (from repo root):
  - unit: `pnpm -C web -r test`;
  - single package: `pnpm -C web --filter @noteit/core test`;
  - typecheck: `pnpm -C web -r typecheck`;
  - lint: `pnpm -C web lint`;
  - E2E: `pnpm -C web e2e`.
- **Test first.** Every task begins by adding failing tests or vectors. Commit only once they pass.
- Never touch `~/Library/Application Support/NoteIt`. Native runs use `NOTEIT_DATA_DIR=<repo>/.selftest/<name>`.
- Native names: targets `NoteIt` (`Sources/NoteIt`) and `NoteItSync` (`Sources/NoteItSync`), tests `Tests/NoteItSyncTests`, bundle id `io.github.rutbergphilip.noteit`. Native env vars are `NOTEIT_*` (`NOTEIT_DATA_DIR`, `NOTEIT_SYNC_SELFTEST`, `NOTEIT_SYNC_CONFIG`, `NOTEIT_LIVE_S3_*`, …); the app still reads the old `INKWELL_*` names as a fallback, but new scripts and docs use only `NOTEIT_*`.
- **Wire identifiers are frozen:** `noteit/v1/`, `noteit/.canary/`, `noteit-key-check`, the manifest field names, AAD contexts and KDF parameters are never renamed (spec §2). Stores from before NoteIt 0.4.0 sit under `inkwell/v1/` and seal `inkwell-key-check`: `connect` copies them to `noteit/v1/` like `RemoteMigration`, and the old key check still verifies. Everything new uses NoteIt names (`noteit-doc`, `@noteit/*`, `NOTEIT_*`).
- **Web UI follows `design/`:** define CSS tokens once, mirroring `Sources/NoteIt/Design/Tokens.swift`, and use token names only; copy follows `design/BRAND.md` (Title Case labels, "NoteIt"). Never hard-code a token value.
- Commits follow Conventional Commits, one or more per task (e.g. `feat(web-core): add AES-GCM cipher`). Never amend, rebase or force-push.
- **UUIDs are uppercase** everywhere they are written (keys and JSON). Inner-meta dates are `YYYY-MM-DDTHH:MM:SSZ`. Envelope, tombstone, device and manifest dates are Double2001 numbers (spec §2.2).
- No third-party runtime scripts, fonts or CDNs. TS must compile in `strict` mode with `noUncheckedIndexedAccess`.
- Comments only where something is non-obvious.

// Every meta write starts from RawMetaOverlay (NoteItSync, program spec §4 rule 5); fields added by this plan are
// written only when non-nil, so revisions of untouched records don't change.
// Each v2 pass starts by resolving pendingBodyVersions entries, and ends with the conversion sweep over
// SyncState.legacyBodies (≤200 records/pass), then the orphan sweep (≤200 deletes/pass), then body repair (spec §3.4.9).
// v2 publish of a doc body (push, conversion, conflict copy, repair) — spec §3.4.9:
//   1 resolve any earlier entry for the note; seal the body once; write the sealed bytes to PendingBodies/<ID>.<V>
//     (next to the state file, atomic); persist pendingPushes[id]=rev + pendingBodyVersions[id]=PendingBody(version: v,
//     tag: baseTag(base.remoteMetaETag) or newTag, phase: .uploading, envelope) → 2 PUT docBody(id,v,tag) If-None-Match:*
//     with the stored bytes: 2xx or 412 → on; anything else → in doubt, stay .uploading, skip the note →
//   3 persist .committing → 4 PUT meta If-Match base / If-None-Match:* (commit point): 2xx → 5; 412 → GET meta: it
//     references v → treat as 2xx; else first attempt (.committing in this step) → delete v best effort, clear pending
//     + bytes; else (.inDoubt) → clear pending + bytes, delete NOTHING (left to the sweep); anything else → persist
//     .inDoubt, delete nothing →
//   5 save base (bodyVersion: v), clear pending + bytes → 6 ONLY if await backend.atomicConditionalWrites(): DELETE
//   previous body If-Match listed ETag (errors ignored); otherwise step 6 is skipped and the previous body is kept
//   (spec §3.4.9 "Committed bodies on stores without atomic conditional writes": a late fallback meta write, e.g. a
//   metadata-only pin, can reference it again). Conversion step 5 and pushDeletion's body delete follow the same rule.
//   Without atomicConditionalDelete(): every "delete v" above (own never-committed versions) and, on a store that
//   still has atomic writes, step 6's previous VERSION are a plain delete(key) (immutable keys); step 6 never
//   deletes a legacy body there.
// Resolving an entry (no clock; a loaded .committing counts as .inDoubt):
//   .uploading + live tag (listed meta == base; newTag: no meta, no tombstone) → re-PUT the stored bytes to the same
//     key, continue at 3 (never a new version). .uploading + stale tag → delete v if listed, drop entry + bytes.
//   .inDoubt + listed meta ≠ base (or a meta exists for newTag) → planner first (adopts our write if it references v);
//     otherwise drop entry + bytes, delete nothing. .inDoubt + listed meta == base → re-send the same commit (same v,
//     tag, revision, precondition; envelope sealed afresh); its 412 is never "first attempt".
// At most one pending version per note per device; a new one only once the old one can't be committed.
// Orphan sweep (no clock, no retention; deletes with If-Match listed ETag). Runs at all only if await
// backend.atomicConditionalDelete(). Then only if await backend.atomicConditionalWrites(): a versioned body is deleted only if (a) the known current meta doesn't
// reference it (or there is no meta) AND (b) tag ≠ baseTag(listed meta ETag) (or no meta), for newTag: a meta
// exists, or no meta but a tombstone; a legacy body under a known doc meta is deleted, and so is every body of a note
// with a tombstone and no meta. Always: unparsable bodies/ names. Without atomic writes the sweep deletes NO body
// (not even a tombstoned note's). Own pending versions are skipped.
// Stranded-body recovery (spec §3.4.9; atomic stores only): a hashed-tag body kept only because its tag is live and
// not our own pending version enters state.strandedBodies; after strandedPasses passes AND strandedAge of this device,
// a meta refresh: requires listed meta == base, noteit-doc, local revision == base.revision, no own pending entry;
// GET meta (listed ETag), decrypt + validate, re-seal the same plaintext (same length), PUT If-Match listed ETag;
// 2xx → base.remoteMetaETag = new; 412 / in doubt → nothing (no pending state). At most maxRecoveryWritesPerPass per
// pass. Legacy metas are never refreshed. newTag bodies of a note with no meta and no tombstone are NEVER deleted or
// recovered automatically (no write can make them stale without racing a valid create); only cleanUpUnusedStorage().
// Same-revision adoption: a pull/conflict whose fetched envelope has base.revision and base.bodyVersion only sets
// base.remoteMetaETag and re-plans with the remote unchanged (pull → none, conflict → push).
public static let bodyRepairGrace: TimeInterval = 86_400
public static let strandedPasses = 20; public static let strandedAge: TimeInterval = 86_400
public static let maxRecoveryWritesPerPass = 5
public static let orphanBodyGracePeriod: TimeInterval = 30 * 86_400   // cleanUpUnusedStorage() only (spec §3.4.9)
// Late-landing mutations (spec §3.4 item 10), every v2 engine run: pushDeletion's tombstone PUT is conditional
// (If-None-Match when the listing has no tombstone for the id, else If-Match its listed ETag; 412 → report.skipped,
// re-planned next pass); deleteIfPresent (SyncEngine.swift:741-745) is replaced by deleteIfUnchanged(key, listedETag)
// (If-Match; 404/412 → leave for the next pass) at all its call sites (:327, :330, :377, :546, :550, :637, :657).
// Only device records and canaries stay unconditional.
// Legacy-body repair (repushBody, resolveConflict's missing payload; legacy envelopes only): only when the body is
// missing from the listing AND atomicConditionalWrites(): PUT notes/<id>.body If-None-Match:* (412 = present, fine).
// A present legacy body is never rewritten; otherwise nothing is written (report + conversion sweep).
