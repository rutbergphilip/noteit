# NoteIt Web Implementation Plan

**Goal:** Ship a self-hostable NoteIt web app (Nuxt) that is a full end-to-end-encrypted sync peer of the native macOS app. It reads and writes the same `inkwell/v1/` store and ships as one Docker image with a volume for homelabs.

**Architecture:**
- **Phase 0 (native):** introduce a portable note body, `noteit-doc` (ProseMirror-compatible JSON, versioned), and store format v2 (`formatVersion: 2`, `features`, envelope `bodyFormat`). Add a new SwiftPM target `NoteItDoc` with an NSAttributedString⇄doc converter. Golden vectors are exported from Swift tests into `fixtures/golden/`.
- **Web:** a pnpm workspace in `web/`:
  - `@noteit/core`: a pure TS port of crypto, formats, planner, engine and storage, verified against the vectors;
  - `@noteit/doc`: schema, TipTap extensions and derivations;
  - a Nuxt 4 SPA. Its Web Worker runs the sync engine with WebCrypto and IndexedDB.
- **Server mode (default):** a Nitro server proxies ciphertext to a disk store or upstream S3. One instance serves several people: accounts (argon2id passwords, optional OIDC), invites, an admin role and quotas, with a fully isolated store namespace per user. Browsers use `/api/storage`; native apps and rclone use an S3-compatible subset at `/s3` with per-user keys.
- **Direct mode:** the same client build, served statically (any static host, or the image with `NOTEIT_MODE=static`), talks straight to the user's S3-compatible bucket over CORS, with the S3 key sealed in IndexedDB under the passphrase.
- **Format upgrade:** automatic. A v2 native client upgrades a v1 store on its first clean pass and converts notes in the background; the web never converts and shows "Open NoteIt on your Mac once to finish setting up web access" on a v1 store.
- **UI:** the NoteIt design system in `design/` (`tokens.css`, `BRAND.md`, `components/`).

**Tech Stack:**
- Swift side: Swift 6.3 / SwiftPM / XCTest and AppKit, for the `NoteItDoc` target.
- Web side:
  - Node 24, pnpm 11, TypeScript 5 (strict), Vitest, fast-check;
  - Nuxt 4 (Vue 3, Nitro node-server), Pinia, TipTap 2/ProseMirror;
  - `idb`, Comlink, DOMPurify, nuxt-security, @vite-pwa/nuxt, `@node-rs/argon2`, `openid-client`;
  - Playwright, `oauth2-mock-server` (mock OIDC provider in tests).
- Deployment: Docker (node:24-alpine) and docker-compose, plus a static tarball. Floci S3 is used for interop tests and the direct-mode browser E2E.

**Spec:** `docs/specs/2026-10-13-web-app-design.md`. Section numbers like "§2.3" below refer to it. The spec's §2 is the byte-level format contract.

## Conventions for every task

- Swift tests: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter <Suite> 2>&1 | tail -20`. App build: `swift build 2>&1 | tail -3` must end with `Build complete!`.
- Web tests (from repo root):
  - unit: `pnpm -C web -r test`;
  - single package: `pnpm -C web --filter @noteit/core test`;
  - typecheck: `pnpm -C web -r typecheck`;
  - lint: `pnpm -C web lint`;
  - E2E: `pnpm -C web e2e`.
- **Test first.** Every task begins by adding failing tests or vectors. Commit only once they pass.
- Never touch `~/Library/Application Support/NoteIt`. Native runs use `NOTEIT_DATA_DIR=<repo>/.selftest/<name>`.
- Native names: targets `NoteIt` (`Sources/NoteIt`) and `NoteItSync` (`Sources/NoteItSync`), tests `Tests/NoteItSyncTests`, bundle id `io.github.rutbergphilip.noteit`. Native env vars are `NOTEIT_*` (`NOTEIT_DATA_DIR`, `NOTEIT_SYNC_SELFTEST`, `NOTEIT_SYNC_CONFIG`, `NOTEIT_LIVE_S3_*`, …); the app still reads the old `INKWELL_*` names as a fallback, but new scripts and docs use only `NOTEIT_*`.
- **Legacy wire identifiers stay:** `inkwell/v1/`, `inkwell/.canary/`, `inkwell-key-check`, the manifest field names, AAD contexts and KDF parameters already shipped and are never renamed (spec §2). Everything new uses NoteIt names (`noteit-doc`, `@noteit/*`, `NOTEIT_*`).
- **Web UI follows `design/`:** import `design/tokens.css` unchanged and use token names only; copy follows `design/BRAND.md` (Title Case labels, "NoteIt"); components follow `design/components/*.md`. Never hard-code a token value.
- Commits follow Conventional Commits, one or more per task (e.g. `feat(web-core): add AES-GCM cipher`). Never amend, rebase or force-push.
- **UUIDs are uppercase** everywhere they are written (keys and JSON). Inner-meta dates are `YYYY-MM-DDTHH:MM:SSZ`. Envelope, tombstone, device and manifest dates are Double2001 numbers (spec §2.2).
- No third-party runtime scripts, fonts or CDNs. TS must compile in `strict` mode with `noUncheckedIndexedAccess`.
- Comments only where something is non-obvious.

    - while it runs, a concurrent `sync()` call waits (the operations are serialized);
    - the session ref is swapped before the first conversion PUT, shown by a backend spy recording the
      order of operations.
  - **Conversion is a revision-preserving meta rewrite:** after A upgrades, peer B's next pass reports
    `pulled == N`, `conflicts == 0`. B's records keep their revisions, and B's applied payloads carry
    `bodyFormat == "noteit-doc/1"`. The converted meta PUTs used `If-Match` with the previous meta ETag.
    `legacyBodies` is empty afterwards.
  - **Conversion 412:** a backend fault makes the meta PUT for note X fail with `preconditionFailed`. X stays
    in `legacyBodies`, `pendingPushes` is clear, and the pass reports `skipped`. On the next pass, X follows
    the planner (here `.pull`) and the following conversion converts it.
  - **Old-client race, before conversion:**
    1. A v1-only engine O (`maxFormatVersion = 1` via the internal test init, holding a pre-upgrade v1
       session) and v2 engine A share a store.
    2. A's `sync()` runs the clean pass. A test hook between the clean pass and the manifest PUT lets O edit
       and push note X as RTFD.
    3. A's conversion of X gets 412. The next A pass pulls O's edit, and the pass after that converts it.
    4. Assert that O's text survives, there are no conflict copies, and X ends with `bodyFormat` set.
  - **Old-client race, after conversion:** O edits X after A converted it. O's push gets 412, O's planner
    reports `.conflict`, and O's `importConflictCopy` fails while decoding `DOC:` (a non-fatal per-record
    error, and the pass continues). O's local edit is unchanged, and the remote X is unchanged.
  - **v1-only refusal:** a v1-only engine refuses a *new* connection to a v2 store with
    `unsupportedFormat(2)`.
