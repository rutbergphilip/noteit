# NoteIt Organise Implementation Plan

**Goal:** Tags v2 (chips, nesting, rename, merge, delete), nested notebooks, smart folders with a query language, ranked search with highlights, a Tasks view with due dates, and reminders written in plain words. Everything is derived from note text or stored in additive records, so older NoteIt versions keep working on the same library and sync store.

**Architecture:** There is no `NoteItOrganise` target. The pure logic goes into `NoteItCore` (Foundation only, macOS and iOS), next to the folding and `FuzzyMatcher` that foundations step 1 moves there:
- the token grammar (tags, `@due`, `@remind`), the tag tree and tag rewriting;
- the notebook tree;
- the query parser, evaluator and rewriter;
- the BM25 ranker and highlighter;
- the task parser and the natural date parser;
- the `SmartFolder` model and the `ImageTextProviding` seam (organise creates both in wave 1; wave 0 doesn't).

The app target adds `NoteStore` extensions (search, tags, notebooks, smart folders, tasks, reminders), the search index v2 as a `DerivedIndex` indexer, sidebar, list and editor UI, a `ReminderScheduler`, and the Local API routes registered through `LocalAPIRouteRegistry`. `NoteItSync` gets one new `RecordKind`, two `RemoteLayout` registry entries and a claim API.

**Prerequisites (wave 0, docs/plans/2026-10-19-foundations.md):** `NoteItCore` with `Notebook`, `NoteMeta`, `SidebarSelection` (including `.today`, `.tasks`, `.tag(path)`, `.smartFolder(UUID)`), text folding and `FuzzyMatcher` (step 1); `ChecklistMarkers` (step 2, Task 2.3); `RawMetaOverlay`, the `RemoteLayout` registry and the per-kind raw-meta lifecycle in `NoteStore+RawMeta` (step 3, Task 3.5); `NoteStore.editBody`, `OpenEditorRegistry` and the `DerivedIndex` registry (step 4); `LocalAPIRouteRegistry` (step 5); the frozen shortcut, hotkey, menu and sidebar tables, `SidebarLibraryRow` and the General settings form with `GeneralSettingsSection` (step 6, Tasks 1.1 and 6.1–6.5). From wave 1: linking's `InlineCompletionController` (linking T4), and automation's `LocalAPIRouteRegistry.extendTags(treeProvider:)` and `NotebookDTOExtending`. The program contract (docs/specs/2026-10-19-program-design.md) wins over this plan.

**Tech Stack:** Swift 6.3 toolchain in Swift 5 language mode, SwiftPM (tools 5.10, macOS 14 and iOS 17), Foundation, CryptoKit (SHA-256 for IDs), SwiftUI/AppKit, UserNotifications, CoreGraphics (idle time). No third-party dependencies. Tests use XCTest through `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`.

**Spec:** `docs/specs/2026-10-19-organise-design.md`

## Conventions for every task

- Test command (from the repository root): `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter <Suite> 2>&1 | tail -20`. Expected: `Executed N tests, with 0 failures`.
- App build: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift build 2>&1 | tail -3` and `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift build -c release 2>&1 | tail -3` must both end with `Build complete!` and 0 errors.
- Never touch real user data in `~/Library/Application Support/NoteIt`. When running the app, set `NOTEIT_DATA_DIR="$PWD/.selftest/<name>"` (run from the repository root; `<name>` is any folder name) (gitignored). Notification checks need the bundled app from `NOTEIT_VERSION=x-test NOTEIT_BUILD=99999999999999 NOTEIT_INSTALL_DIR="$PWD/.selftest/app" ./scripts/build_app.sh`, run as `NOTEIT_DATA_DIR="$PWD/.selftest/<name>" .selftest/app/NoteIt.app/Contents/MacOS/NoteIt`.
- Commit after each task with Conventional Commits, for example `feat(search): rank results with bm25`. Scopes: `organise`, `search`, `tags`, `notebooks`, `smart-folders`, `tasks`, `reminders`, `sync`, `docs`. Never amend, rebase or force.
- No `#Preview`. Comments only where something is non-obvious.
- Everything this plan adds to `NoteItCore` is `public` and `Sendable`. It imports Foundation only (CryptoKit is allowed for hashing); `ImportHygieneTests` must keep passing.
- `NoteStore` members that extension files need lose `private` (become internal), nothing more. Keep `@MainActor` on everything store-side. Nothing here adds a body-change hook to `NoteStore.swift`; derived data goes through the `DerivedIndex` registry and text changes through `editBody`.
- Every new menu command adds its `MenuShortcutCommand` case and default, deletes its row from foundations' `PlannedMenuShortcuts`, and updates `MenuShortcutRules` and `docs/keyboard-shortcuts.md` in the task that adds it. `MenuShortcutDefaultsTests` (foundations 6.1) must keep passing. The `HotkeyAction` case updates the `ShortcutsSettingsView` tile switch and the `AppDelegate` handler switch in the same task.
- Local API routes are registered with `LocalAPIRouteRegistry.shared.register`, route ids `organise.<name>`, an explicit scope and `APIErrorCode` errors only.
- New UI strings follow the spec's wording exactly. New user-visible behaviour gets a line in `docs/` in the task that adds it, or in Task 23.
- Performance budgets are checked by tests using `measure`-free timing (`ContinuousClock`) with generous CI margins: search 5k notes ≤ 30 ms (assert ≤ 60 ms in debug), tasks build ≤ 50 ms, tag rename of 500 notes ≤ 3 s.
